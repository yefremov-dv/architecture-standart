### <a name="_qmphm5d6rvi3"></a>**Решение**
Диаграммы контекста и контейнеров в модели C4 находятся в файле **task4-mvp-tobe.drawio**
Обновленные элементы ИТ-ландшафта указаны **зеленым цветом**.

В дополнение к существующим требованиям MVP, по согласованию со службой безопасности, было принято решение использовать функционал коннекторов Kafka, который полностью покрывает требования банка и партнерского кол-центра. Доработка системы партнерского кол-центра по отображению ставок из передаваемого файла в рамках SFTP обмена будет реализована партнером самостоятельно к началу тестирования со стороны команды банка.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Альтернативным решением была реализация интеграции между партнерским и собственным КЦ для устранения взаимодействия внешней системы с интеграционным шлюзом банка. Такой вариант интеграции является более безопасным.
От данной идеи отказались, тк доработка системы собственного КЦ невозможна без привлечения подрядчика, который не готов реализовать это в требуемый срок.

**Недостатки, ограничения, риски**

Ключевой риск - утечка банковской тайны. Было принято решение о заключении дополнительного NDA с партнерским КЦ, в котором детально прописаны случаи обмена информацией по депозитным ставкам.

**Список крупных задач для какждой системы из ADR**
1. Система кол-центра:
    - Т1 реализовать прямую интеграцию между шлюзом и системой кол-центра со стороны кол-центра
2. Сервис распросранения ставок по депозитам
    - Т2 согласовать формат взаимодействия между сервисом и партнерским кол-центра
    - Т3 реализовать функциональность для генерации требуемого файла со ставками
3. Система партнерского кол-центра
    - Т4 реализовать функциональность приема файла по SFTP и журналирования изменения ставок
    - Т5 доработать интерфейс сотрудников партнерского кол-центра для корретного отображения ставок
4. Интеграционный шлюз
    - Т6 добавить интеграцию через SFTP на адрес партнерского кол-центра
5. Для всех систем перед запуском MVP
    - Т7 обучение персонала и подготовка в запуску
    - Т8 запуск MVP в продуктивной среде
